# Backend configuration

The API uses MongoDB through Mongoose. Copy `.env.example` to `.env` for local
development and fill in the required settings. `.env` is intentionally ignored
by Git; production secrets belong in the hosting provider's secret manager.

Required settings:

- `MONGO_URI`: database connection string.
- `JWT_SECRET`: at least 32 random characters; generate with
  `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`.
- `ADMIN_USERNAME`: the only configured admin login name.
- `ADMIN_PASSWORD_HASH`: bcrypt hash generated by `npm run hash-admin-password`.
- `CORS_ORIGINS`: comma-separated exact browser origins; required in production.
- `BUSINESS_TIME_ZONE`: IANA time zone used to reject past appointment dates
  (defaults to `Asia/Kolkata`).

Set `FAST2SMS_API_KEY` before enabling OTP login. On delivery failure the API
returns an error and invalidates the unsent code. A development-only OTP
response is available only when `NODE_ENV` is not `production` and
`OTP_INCLUDE_IN_RESPONSE=true`.
Mobile OTP requests include the selected sign-up/sign-in intent; the API checks
account existence before sending an SMS and refuses mismatched choices. This
reveals account existence to the requester, so OTP requests are rate-limited by
IP and phone number.

Customer PIN codes are checked against the India Post public postal lookup
service. Profile saves require a recognized PIN code; customers enter their
locality and street address themselves. Backend hosting must allow outbound
HTTPS access to `api.postalpincode.in`; temporary provider outages are reported
as a retryable service error.

## Run and test

```sh
npm install
npm test
npm start
```

The current rate limiter is process-local. Before using multiple API replicas,
replace it with a shared store such as Redis and configure proxy trust only for
the known hosting proxy. The API also needs production monitoring, backup
restore tests, and audit events for admin changes before it should be treated
as production-complete. Customer mobile sessions use rotating refresh tokens
stored as hashes in MongoDB; sign-out revokes the current device session, and
each account is limited to ten active sessions.

The previously committed backend `.env` should be considered exposed. Keep the
local file out of Git, rotate all values that were ever real, and do not reuse
the old built-in admin password.
